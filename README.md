# remy

A small recipe book. Each recipe has a **Recipe** tab (one clean recipe,
generated by Claude from your notes and editable) and a **Notes** tab: a
Jupyter-style notebook of numbered cells you insert, move, merge and delete
from a toolbar. Three cell types: **Text**, **Image** (photo upload, stored
in the database), and **Voice** (dictate with the browser's speech
recognition or, when that's missing, Groq; the transcript becomes the note).
The home page is the pass: an order rail with up to three starred recipes
clipped up as tickets, and the counter below it with the range, a pot and
skillet, and the cookbook standing beside them. On desktop the whole scene
is zoomed to fill the window. Clicking the book lifts it to the camera,
opens it, flips a couple of pages (each showing a random recipe) and lands
on the cookbook (`#/book`): search, tag filter and sort on top and the
table of contents below, with the first photo of each page. The tickets
on the pass are paper slips with the order handwritten on them. Star a page (from its
header or the cookbook) to hang it on the pass; a fourth star demotes the
oldest one instead of refusing.

A **Flask + SQLite** JSON API plus a no-build static frontend, swapping to
**Postgres/Supabase** via `DATABASE_URL`, isolated in its own schema so it can
share one database with other apps without colliding. Deploys to Render as a
Docker web service.

## Stack

- **[Flask](https://flask.palletsprojects.com/)** — JSON API under `/api`, serves `web/` and `brand/tokens.css`
- **Vanilla HTML/CSS/JS** frontend in `web/` (hash-routed, no bundler), styled from `brand/tokens.css`; notebooks autosave as you type
- **Installable PWA**: `web/manifest.webmanifest` + `web/sw.js` (network-first shell cache, API never cached)
- **Voice cell**: speech-to-text with the browser's own recognizer (Web Speech API, free) by default, falling back to Groq's Whisper API (`GROQ_API_KEY`, about $0.04 per hour of audio) when the browser has none or it fails
- **Recipe tab**: the page's notes become one clean recipe through the [Anthropic SDK](https://github.com/anthropics/anthropic-sdk-python) and `claude-haiku-5-5` (`ANTHROPIC_API_KEY`); key unset ⇒ Generate and Fix are disabled
- **[Flask-SQLAlchemy](https://flask-sqlalchemy.palletsprojects.com/)** over **SQLite** by default
- **Postgres/Supabase** when `DATABASE_URL` is set, pinned to `DB_SCHEMA`
  (the `stackify-v1` no-collision schema pattern)
- **gunicorn** in the container; Render Blueprint in `render.yaml`

## Getting started

```bash
cd backend
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
python wsgi.py            # http://localhost:5000
```

On first run it creates `backend/instance/remy.db` and seeds one recipe. The
UI is at `/`; `GET /api/health` reports the active backend + schema.

To use a different database, copy `backend/.env.example` to `backend/.env` and
set `DATABASE_URL`, or export it in the shell.

### Sharing one Postgres/Supabase project (no-collision schema)

```bash
# Supabase SESSION pooler host (port :5432 — required, see below)
export DATABASE_URL='postgresql://postgres.<ref>:<pw>@aws-0-<region>.pooler.supabase.com:5432/postgres'
export DB_SCHEMA=remy        # remy's tables live here; default is public
```

- **`DB_SCHEMA` is validated** as a bare SQL identifier
  (`^[A-Za-z_][A-Za-z0-9_]*$`) before it's interpolated, then created
  idempotently (`CREATE SCHEMA IF NOT EXISTS`) on first boot.
- **`search_path` is pinned per connection** via libpq `options`, so every
  unqualified query resolves inside remy's namespace.
- **Session pooler required.** Pinning `search_path` needs a session-mode
  connection; the transaction pooler (`:6543`) would drop it.
- **`postgres://` URLs are normalized** to `postgresql+psycopg://` (psycopg 3).
- **Unset `DATABASE_URL` → SQLite, unset `DB_SCHEMA` → `public`.**

Migrate an existing SQLite database into the shared schema (refuses to run into
non-empty tables):

```bash
cd backend
python scripts/migrate_sqlite_to_pg.py [path/to/remy.db]
```

Rebuild the tables from the current models after a schema change (destructive):

```bash
cd backend
python reset_db.py --yes
```

### Cells, images, and the Voice cell

A recipe's `blocks` is the ordered cell list as JSON. `body` is derived from
the text of text and voice cells, so search and list previews keep working.

Cells are raw notes; nothing formats them individually, the Recipe tab does
that for the whole page. While a cell's text is focused a `✓ Done` button
appears under it to leave editing explicitly. `⤵ Merge…` in the toolbar
enters a selection mode: tick two or more text or voice cells in any order
(images can't be ticked), press Merge, and a modal shows the combined text
with a warning that it can't be undone before anything changes. The merged
cell takes the first ticked cell's place; it is a voice cell only when every
ticked cell was one, keeping their transcripts.

Each page opens on the **Recipe** tab (a brand-new page opens on Notes,
where you add content). **Notes** is the cell notebook. **Recipe** is the
one clean recipe. `✦ Generate from notes` appears before the first
generation and again only when a note has changed since the last one (the
server stores a hash of the notes it read, and every recipe response carries
`notesChanged`); while the recipe is current the button is absent and that
absence is the signal. It sends every text and voice cell, in
order, to `POST /api/recipes/:id/compile`, which asks `claude-haiku-5-5` to
merge them (later notes win on conflicts, repetition removed, nothing
invented) and stores the result in `compiled`. The compiled recipe is
markdown in a fixed layout (`## 🧂 Ingredients`, `## 🍳 Equipment` as bare
items with no explanations, `## 🔪 Steps`, optional `## 📝 Notes`, an
optional `⏱` line) and the tab renders it with the display
face for headings, copper-numbered steps and generous spacing, via a small
built-in renderer (headings, lists, bold, italic; input is escaped first).
Ingredients are listed as bought from the store; every prep action is its own
step. Press `Edit` for the raw text, autosaved; while editing, highlight any
span and a bar appears: type what should change (or nothing, to just tidy
it) and `✦ Fix` sends the full text, the span and the instruction to
`POST /api/recipes/revise`, which returns a replacement for that span only.
Search covers the compiled recipe too.

In the notebook: `+ Text`, `+ Image`, `+ Voice` insert after the selected cell
(or at the end). A selected cell takes ↑ ↓ and `× cell` from the toolbar or
its own hover tools. With a cell selected and no field focused: `j`/`k` or
the arrow keys move the selection, Shift+arrow moves the cell, `Enter` edits,
`Escape` leaves the field, `d` deletes.

```
{"id", "type": "text",  "text"}
{"id", "type": "image", "asset", "caption"}
{"id", "type": "ai",    "text", "transcript"}
```

- **Images** upload to `POST /api/recipes/:id/assets` (multipart `file`, image
  only, 8 MB cap; the UI shrinks photos to 1600px JPEG first) and are served
  from `GET /api/assets/:id`. Bytes live in the database, so they survive
  Render's ephemeral disk. Assets no block references are pruned on save.
- **Voice** is a cell with a transcript. Press Dictate: a full-screen
  recording panel opens with a pulsing indicator, a live mic level meter, a
  timer, the words as they land, and a big Done button (Cancel or Escape
  discards). Recognition is the browser's own `SpeechRecognition` when it
  works (Chrome, Edge, iOS Safari; Chrome hands the audio to Google's
  engine), restarted automatically when the browser stops it on silence.
  If the API is absent (Firefox) or fails at start (a phone without Google's
  speech engine reports `network` or `service-not-allowed`), the panel
  switches to cloud transcription and remembers that choice: raw PCM is cut
  into chunks at the first pause after 5 s (hard cut at 10 s), encoded as
  16 kHz WAV and posted to `POST /api/transcribe`, which forwards it to
  Groq's `whisper-large-v3-turbo` with the previous chunk's text as the
  prompt. Up to two chunks in flight, results applied in order while you
  keep talking. The panel says which engine is in use. Edit the transcript
  if needed, press Format.
- Groq limits (same on the free and developer plans): 20 requests/min, 2000
  per day, 2 hours of audio per hour, 8 hours per day. A 429 shows in the
  panel as a hiccup and the chunk is skipped. Chunk sizing keeps continuous
  talking at roughly 6 to 12 requests a minute. The transcript goes to
  `POST /api/recipes/draft`, which asks `claude-haiku-5-5` for
  `{title, body, tags}` through structured output. The cell becomes an `ai`
  block holding the formatted text (the output) and the transcript (the
  input, shown collapsed). An untitled page takes the drafted title; empty
  tags take the drafted tags. Needs `ANTHROPIC_API_KEY`; otherwise the
  endpoint returns 503 and `/api/health` reports `draft: false`. Transcripts are capped at 8000 characters and output at 2000
  tokens, well under a tenth of a cent per run.

The app has no auth: anyone who can reach the URL can spend your key. Fine
for a personal deploy; add a secret header or a rate limit before sharing the
link widely.

Schema note: `create_all()` only creates missing tables. Columns added after
the first release are listed in `ADDED_COLUMNS` in `remy_api/__init__.py` and
added in place at boot when absent, so an older database upgrades itself
without a reset. `reset_db.py --yes` / `REMY_DB_RESET=1` remain for a
destructive rebuild.

Additional env vars: `DATABASE_SSL=disable` (local plaintext Postgres only),
`PGPOOL_MAX` (max pool connections, default 3), `REMY_DB_RESET=1` (drop +
recreate tables at boot — remove once the schema is live). See
`backend/.env.example`.

## Deploy (Render Blueprint)

1. Push to GitHub.
2. In Render: **New → Blueprint**, point it at this repo. It reads `render.yaml`
   and creates one Docker web service.
3. Set the secret **`DATABASE_URL`** in the service's Environment tab — the
   Supabase **Session pooler** URL (`:5432`). `DB_SCHEMA` defaults to `remy`.
   Leave `DATABASE_URL` unset to run on ephemeral SQLite (data resets on deploy).
4. Deploy. Health check is `/api/health`.

Build the image locally the same way Render does:

```bash
docker build -t remy .
docker run -p 5000:5000 -e DATABASE_URL=... -e DB_SCHEMA=remy remy
```

## API

Base path `/api`. Fields use camelCase keys. A recipe is
`{id, title, blocks: [..], body, tags: [..], createdAt, updatedAt}`; `tags` is
accepted as a list or a comma-separated string and normalized to lowercase,
deduped. Writes take `blocks`; a legacy `body` string becomes one text block.

| Method   | Path            | Purpose                                                          |
| -------- | --------------- | ---------------------------------------------------------------- |
| `GET`    | `/health`       | liveness + active backend/schema                                 |
| `GET`    | `/recipes`      | list; `?q=` searches title/body/tags, `?tag=` filters, `?starred=1`, `?sort=updated\|created\|title\|starred` |
| `POST`   | `/recipes/:id/star` | star (max 3; the oldest star is demoted) → `{recipe, demoted}`      |
| `DELETE` | `/recipes/:id/star` | unstar                                                           |
| `POST`   | `/recipes`      | create `{title?, blocks?, tags?}` (empty body ⇒ an Untitled page) |
| `GET`    | `/recipes/:id`  | read one                                                         |
| `PUT`    | `/recipes/:id`  | partial update of `title`, `blocks`, `tags`, `compiled`          |
| `DELETE` | `/recipes/:id`  | delete                                                           |
| `GET`    | `/tags`         | `[{tag, count}]` across all recipes                              |
| `POST`   | `/recipes/:id/assets` | multipart image upload → `{id, contentType, size, url}`     |
| `GET`    | `/assets/:id`   | the stored image bytes                                           |
| `POST`   | `/transcribe`   | multipart audio chunk (+ optional `prompt`) → `{text}` via Groq; 503 when off |
| `POST`   | `/recipes/draft` | `{transcript, title?}` → `{title, body, tags}` via Claude; 503 when off |
| `POST`   | `/recipes/:id/compile` | every text/voice cell → one clean recipe stored in `compiled`; returns the recipe |
| `POST`   | `/recipes/revise` | `{text, start, end, instruction?}` → `{replacement}` for that span; nothing saved |
